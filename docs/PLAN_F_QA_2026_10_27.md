# PlanF verification — 27 October 2026

Implemented optional, presentation-only scanning help across the authored assembly camera
targets. Enable **Settings → PlanF guided scanning help** after updating through Android Studio.
The setting starts disabled. See [the manual](PLAN_F_SCAN_HELP.md) for controls and behavior.

## Changes

- `PlanFSession`: five-second ready-scan timer; one automatic offer per attempt; no background
  time counting; navigation/rescan reset; manual help suppression of repeated automatic prompts.
- `PlanFReferenceCatalog`: current-target positive photos only, up to six variants; explicit
  phase roles prevent rejected orientations, wrong Phase 2 sides and loose Phase 7 parts from
  being offered as installed-work examples. Existing reference objects and regions are reused.
- `PlanFReferenceImageView`: bounded asynchronous photo loading and authored feature-region
  highlighting, explicitly labeled as reference imagery rather than a live detection.
- `PlanFScanHelpController`: non-verifying help window, fixed stacked actions, independent
  scrolling content, automatic dismissal on verification/navigation/pause/disable/destruction.
  It receives no recognizer, phase-transition callback or progress writer.
- `AssemblyActivity`: observes existing ready/verified state through the existing 250 ms status
  monitor; disabled path returns before target/photo work. Camera matching and tracking continue
  behind help. `PreferencesManager`, settings resources and toolbar expose the optional control.

No new camera, inference, descriptor extraction, reference asset, model or dependency was added.
The existing matching policies, telemetry evidence, LK bridge, bounding tracker, dynamic outline
renderer and phase checkpoint classes were not edited for PlanF. Earlier uncommitted vision work
in this checkout was retained.
